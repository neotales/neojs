## Two runtimes, one module policy

NeoJS is two crates with different jobs. They share executable-extension policy, not a feature set.

| | V8 runtime (`neojs`, `neojs-core`) | NeoJS Lite (`neojs-lite`, `neojs-lite-core`) |
| --- | --- | --- |
| Engine | V8 through `deno_core` | QuickJS through `rquickjs` |
| ECMAScript modules | Yes | Yes |
| Erasable TypeScript | Yes, `.ts` and `.mts`, no type checking | **No** |
| Built-in `neo:` modules | Thirteen modules documented here | **No** |
| Host asynchrony and timers | Through the runtime and `deno_core` | **No** timers or host Promise integration |
| Remote HTTPS loading | Opt-in through the V8 CLI/runtime | **Not implemented** |
| Permissions or sandbox | **None** | **None** |

## What this site covers

- **The V8 command line**: `neojs <file>`, `neojs test`, remote flags, and exit codes.
- **Every built-in module** currently implemented: `age`, `assert`, `chars`, `console`, `crypto`,
  `os`, `path`, `slices`, `ssh`, `stdio`, `strings`, `test`, and `uuid`.
- **The embedding APIs**: `neojs_core::Runtime` and `neojs_lite_core::Runtime`.
- **The SQL foundation**: `neojs-dbapi`, including the fact that only SQLite is wired end to end.
- **The unsupported list**: the things that are deliberately absent, so a missing feature is not
  mistaken for a bug.

## Not Node.js

NeoJS runs ECMAScript modules, but it is not a Node compatibility layer. `node:`, `npm:`, `jsr:`,
`http:`, `data:`, and `blob:` imports are rejected. CommonJS, `require`, `process`, import maps,
module type attributes, and a permission system are not implemented. See
[Limits and unsupported features](/limits/).
